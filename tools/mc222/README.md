# mc222: the multiplicative complexity of the 2×2 matrix product over F₂ is 7

This folder checks, by two independent computations, the following statement:

> **Claim.** Over F₂, no XOR-AND circuit with 6 (or fewer) AND gates computes the four
> functions c_ij = a_i1·b_1j ⊕ a_i2·b_2j (i, j ∈ {1,2}) of the eight inputs
> a11, a12, a21, a22, b11, b12, b21, b22.
> Strassen's algorithm uses 7, so the multiplicative complexity is exactly 7.

The two computations are:

* **(A)** an exact search over circuit states, written in Rust (`src/main.rs`);
* **(B)** a SAT encoding (`gen_cnf.py`) split into 1080 cubes. Each cube is solved by
  CaDiCaL 2.1.3, which writes an LRAT proof, and every proof is checked with `lrat-check`
  from the drat-trim repository.

The two share no code. What they do share is the model and two short lemmas (§2), which
are proved on paper below. They also share the idea of orbit reduction for the first gate,
but this is coded twice: Rust in `main.rs`, Python in `orbits.py`. Both give the same
72 representatives and the same orbit sizes.

Neither (A) nor (B) is derived from the earlier program `research/mm/lab/mc_span.c`, which
was not read. Only the notebook's description of the *model* was read, and it agrees with
the model below: S_j = span{1, inputs, G_1..G_j}, XOR and constants free.

That script evaluates the circuit on all 2ⁿ inputs and compares the outputs with the target

## 1. Model

A circuit is a sequence of AND gates g_1, …, g_k:

* each gate is g_i = L_i · R_i, where L_i and R_i are F₂-affine combinations of the inputs
  x and of g_1, …, g_{i−1};
* each output must be an F₂-affine combination of the inputs and of all gates;
* everything is a Boolean function, so x² = x;
* intermediate degrees are unrestricted.

Write S_j = span{1, x_1, …, x_8, g_1, …, g_j}. This is a space of truth tables, i.e. vectors
in F₂^256. Let A = S_0 be the affine functions and T = span{c11, c12, c21, c22}.

* A gate is any product u·v with u, v ∈ S_{j−1}.
* The circuit computes the targets exactly when T ⊆ S_k.
* Constants and linear terms are free, as required.

## 2. Reductions and why they lose no circuits

**N1 (constants, and the gate depends only on its plane).** Let u, v ∈ S_{i−1}. Then

* (u+1)·v = u·v + v,
* u·(u+v) = u·v + u, because u² = u.

So changing a gate by an element of S_{i−1} leaves every later S_j unchanged. Later gates
and outputs can be re-expressed in terms of the changed gate. Hence:

* the constants in L_i, R_i may be taken to be 0;
* (L_i, R_i) may be replaced by any basis of span{L_i, R_i}, for example its reduced
  row-echelon basis (the SAT encoding does this);
* if L_i and R_i are dependent, or g_i ∈ S_{i−1}, the gate can be deleted.

A circuit with fewer than k gates can be padded to exactly k by appending gates such as
x_0·x_1. So "≤ k AND gates" is the same as "exactly k gates in this normal form".

**N2 (rem lemma).** Let rem(S) = dim(S+T) − dim S, so rem(S_0) = 4 (the targets are
independent modulo A, which the code checks). Suppose a gate g increases the dimension.

* If g ∈ (S+T) \ S, then S+T is unchanged and dim S grows by one, so rem drops by 1.
  Call such a gate a *reducer*. Then S' = S + ⟨t⟩ for some t ∈ T.
* Otherwise both dimensions grow, so rem is unchanged. Call such a gate a *helper*.

So with b gates left, a state with rem > b cannot be completed. A circuit with k gates
(each increasing the dimension) has exactly k − 4 helpers.

**N3 (symmetry).** Let G be generated by the following maps, as substitutions of inputs:

* (A, B) ↦ (P A Q⁻¹, Q B R⁻¹) for P, Q, R ∈ GL₂(F₂);
* (A, B) ↦ (Bᵀ, Aᵀ).

G has 432 elements. Every g ∈ G is linear and invertible, and f ↦ f∘g maps A + T onto
itself. Both programs check this on truth tables.

Substituting x ↦ g(x) into every gate of a circuit gives another circuit, with the same gate
count, whose space is S_k∘g ⊇ (A+T)∘g = A + T. The first gate is always a product of two
linear forms. Under the substitution its plane span{a, b} of coefficient vectors moves along
its G-orbit. So it is enough to try one first-gate plane per orbit.

There are 10795 planes and 72 orbits. The sizes (4, 6, 6, 9, …, 432) sum to 10795. Rust and
Python compute the same representatives independently. Translations x ↦ x + d also preserve
A + T, but they act trivially on the normalised first gate, so they are not used.

**H (helper lemma, used only by the SAT cubes).** If any circuit with ≤ 6 ANDs exists, then
one exists with:

* exactly 6 gates in normal form N1;
* first gate equal to an orbit representative (N3);
* a set H of 2 gate positions such that every gate i ∉ H satisfies
  g_i ∈ W_i := A + T + span{g_j : j ∈ H, j < i}.

*Proof.*

1. Take a circuit with the fewest gates, m ≤ 6. By N1, every gate increases the
   dimension. By N2, it has m − 4 helpers.
2. Append 6 − m padding gates and let H contain all helpers and all padding gates; then
   |H| = 2. (m ≤ 3 is impossible, because rem starts at 4.)
3. By induction on i, S_{i−1} ⊆ W_i. Each earlier gate is either in H, or is a reducer
   g_j ∈ S_{j−1} + T ⊆ W_j ⊆ W_i.
4. So every reducer satisfies g_i ∈ S_{i−1} + T ⊆ W_i.
5. These spaces do not change when a gate is altered by an element of S_{i−1}. So the
   property survives the N1 normalisation and the N3 substitution, because A + T is
   G-invariant.

The SAT run covers all 15 two-element sets H ⊂ {0..5}. It does not assume that the first
gate is a helper, although that is true: a product of two linear forms has alternating rank 2,
while every nonzero element of T has rank 4 or 8. ∎

## 3. Method (A): exact search (`src/main.rs`)

**State and search.** A state is S, stored as truth-table generators. It is canonically
keyed by the fully reduced echelon basis of S modulo A. This key is exact: failed states are
stored as full keys in a hash set, so a hash collision can never merge two states. The search
is a DFS with budget b = k − j and the N2 cut rem > b ⇒ fail. The successors of S are:

* **Reducers.** Fix u ∈ S/⟨1⟩. Then v ↦ u·v is linear. Gaussian elimination on the
  vectors u·v_i, reduced modulo S+T and tagged with their coordinates on T/S, gives every
  class t ∈ (S+T)/S that some product u·v hits. The union over all 2^{dim S − 1} values of u
  is exactly the set of reachable classes. The successor for each class is S + ⟨t⟩. This
  uses bilinearity: the products of basis pairs are reduced once, and u runs through a Gray
  code.
* **Helpers.** These are tried only if rem < b (N2). The program enumerates every plane
  {u, v} of S/⟨1⟩ (one pair per plane, u < v < u⊕v). It keeps each product u·v ∉ S+T,
  deduplicated by its exact reduced residue modulo S. That residue determines S + ⟨u·v⟩
  uniquely.

**Roots and memo.** The roots are the 72 orbit representatives of the first gate (N3). The
memo of failed states is a sound cache: failure depends only on S, because b is fixed by
dim S. It is cleared per root, which makes per-root statistics deterministic.

**Consistency check.** Running a *different* member of the same orbit as the root (option
`--member`) gives the same number of states as the representative. This was checked for
6 orbits.

## 4. Method (B): SAT with checked proofs (`gen_cnf.py`, `run_sat.py`)

**Variables and constraints.** The encoding works on the truth tables, at all 256 input
points:

* Each gate i has coefficient variables for L_i and R_i, over x_0..x_7 and g_0..g_{i−1}.
  The pair must be the reduced row-echelon basis of a 2-dimensional space (N1).
* Each output has free coefficients: constant, x's and gates.
* The linear part in x at point p is computed as X(p) = X(p − 2^h) ⊕ s_h, where h is the
  highest set bit of p.
* XOR uses Tseitin clauses with constant folding.

**Cubes.** Each cube fixes gate 0 to an orbit representative (N3). It also adds, for every
gate i ∉ H, a coefficient vector expressing g_i as a member of W_i at all 256 points
(lemma H).

Without cubes, the instance for root 0 had not finished after 275 s. With cubes, each one
takes 0.03–17 s.

**Proofs.** CaDiCaL writes text LRAT (`--lrat=true --binary=false`) and `lrat-check`
verifies it. A negative test was run: a truncated proof gives `NOT VERIFIED`. Proofs are
not kept. `out/sat_k6/results.tsv` records, per cube:

* verdict and check result;
* solve and check times;
* CNF and LRAT sizes and sha256.

CaDiCaL is deterministic, so rerunning reproduces identical proofs; the hashes can be
compared. This was checked by regenerating root 0, H = {0,1}: the CNF and LRAT sha256 both
matched. Per helper set, almost all the work is in H = {0,1} (685 s), {0,2} (263 s) and
{0,3} (116 s). Every cube with 0 ∉ H is UNSAT in about 0.1 s. `summarize_sat.py` checks that all 72 × 15 cubes are present, UNSAT, and verified.

Do not use the CaDiCaL development head (3.1.0). It printed only a partial model, which my
decoder misread. All runs use the tagged release `rel-2.1.3`.

## 5. Trust base

* **Both methods:** the model and lemmas N1–N3 (proved above). The symmetry group is
  computer-checked; for H only lemma H is needed in (B).
* **(A):** `src/main.rs` (~800 lines, no dependencies) and the Rust compiler.
* **(B):**
  * `gen_cnf.py`: the CNF must say what it claims. This is validated by the known
    SAT/UNSAT cases above and by decoding SAT models into circuits that
    `verify_circuit.py` accepts.
  * `orbits.py`.
  * `lrat-check.c` from drat-trim, commit 2e3b2dc.
  * CaDiCaL is **not** trusted.
* **Not trusted anywhere:** the earlier `mc_span.c`.

## 6. Re-running

```
./run_all.sh [ext_dir]    # clones and builds CaDiCaL rel-2.1.3 and drat-trim, then runs everything
```

Individual pieces:

```
cargo build --release
target/release/mc222 mm222 6                  # exact search, 72 orbit roots, 4 threads
target/release/mc222 mm222 6 --no-orbits      # all 10795 first gates (≈150× slower)
target/release/mc222 <problem> <k> [--prefix "a,b;c,d"] [--member] [--roots i:j] [--threads N]
python3 orbits.py                             # writes plane_orbits.txt
python3 run_sat.py <cadical> <lrat-check> 3 6 # 1080 cubes, resumable; out/sat_k6/results.tsv
python3 summarize_sat.py out/sat_k6/results.tsv
python3 verify_circuit.py <circuit.txt>
```

The problems are `mm222`, `mm221`, `polymul2`, `polymul3` and `f4`.

Build artefacts, CNFs, proofs and scratch output are git-ignored (`target/`, `out/`). The
small permanent records are in `results/`:

* `sat_k6_results.tsv`: one line per cube, with sha256 and size of the CNF and the LRAT
  proof;
* `exact_k6_orbits.log`: the Rust per-orbit log;
* `circuit_mm222_7_p2.txt`: a 7-AND circuit found by the search, which `verify_circuit.py`
  accepts.

To regenerate any proof, run `gen_cnf.py mm222 6 --root a,b --helpers i,j` and then
`cadical -q --lrat=true --binary=false x.cnf x.lrat`.

A from-scratch k=7 search in (A), with only Strassen's first product fixed, was stopped after
15 min without a result. With 3 helpers allowed, the space is about 42k × 170k helper pairs.
k=7 was therefore validated with 2 or 3 fixed products in (A), and from scratch in (B).
